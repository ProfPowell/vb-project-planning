Overview

The <capacity-plan> stitches the planning chain together visibly. It reads three numbers — capacity from a paired <iron-triangle>, quality spend from a paired <quality-target>, and feature spend from slotted elements with data-capacity-cost — and renders a four-row ledger with proportional bars: capacity vs quality vs features vs slack.

It's the answer to "where did my capacity go?" Without it, the chain is implicit; with it, the math is the first thing the team sees on the requirements page.

The arithmetic

Plain subtraction:

slack = capacityPoints − qualityCriticalSum − featureCostSum

Capacity comes only from the bound <iron-triangle>. When no triangle is bound, or its capacity is 0, capacity and slack show as ∞ and the quality and feature bars scale against each other instead of against a budget. A data-capacity-points fallback on the <quality-target> feeds that target's own budget, not this ledger.

With a finite budget, bars scale against the larger of capacity and total spend, so an overdrawn plan still fits the track. When slack goes negative its number turns red, the ledger gets an error-coloured outline (:state(overdrawn)), and capacity-plan:overdrawn fires. The event fires on every crossing of zero, in either direction, including the first render if the plan starts out overdrawn.

For server-rendered planning surfaces or programmatic flows, set featureSum directly; property override wins over slot inference. Set it to null (or anything that isn't a number) to go back to summing the children. Mutation observation re-renders automatically when children are added or removed or a child's data-capacity-cost changes.

Accessibility

The ledger is a <dl aria-label="Capacity ledger">: each row is a <dt> label with its value in a <dd>, so the capacity / quality / features / slack breakdown reads as text without relying on the bars, which carry no text. Bars adopt VB theme tokens so they auto-adapt across light, dark, and brand themes. The overdrawn state is conveyed by the signed slack value (e.g. "-3 pts"), not by colour alone. The ledger is not a live region: changes are not announced, so pair it with the bound components' own announcements, or add an aria-live wrapper if the ledger is the only feedback.
