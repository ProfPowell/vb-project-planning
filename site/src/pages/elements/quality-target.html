Overview

The <quality-target> component is the planning surface's quality decision. The polygon IS the picker — each of the 11 ility axes is a clickable hit-target that opens a per-ility <dialog> with a level radio group (Critical / Important / Acceptable / Not relevant) plus a required rationale when Critical. The same SVG shows the chosen vector on three level rings, with a centre readout of Critical spend against the project's capacity, so picking and reading happen on the same surface.

Pair it with <iron-triangle> via data-bind-to and the capacity comes from the project shape. "Quality" is the word the surface uses; the older "NFR" jargon and its separate compass + radar pair collapse into this one component, two roles.

Per-axis editors

Click an axis (or focus it and press Enter / Space) to open its dialog. Each editor has a radio group for the four priority levels, a <form-field>-wrapped rationale textarea (required when Critical, ≥10 chars by default via data-min-rationale), and Cancel + Save buttons; the dialog uses method="dialog" so submit closes it. Save is refused with an inline message until a level is picked and, for Critical, the rationale is long enough. The marker and label colour follow the level: red Critical, amber Important, green Acceptable, muted Not relevant. The polygon is the closed shape across all picked axes; unpicked ilities don't pull the shape toward the centroid.

Capacity budget

Every ility has a cost when Critical. Only Critical picks spend capacity; Important, Acceptable, and Not relevant are free. The running total is criticalSum:

criticalSum = Σ costWeights[ility] for every ility picked "critical" overBudget = criticalSum > capacityPoints

The centre of the radar shows criticalSum over the capacity ("5" above "of 4"), or "unbounded" when no capacity is known. Capacity resolves in this order: a bound <iron-triangle>'s capacityPoints, then data-capacity-points, then the capacityPoints property, then unbounded. There is no envelope polygon; the three level rings are the only backdrop.

Going over budget is allowed, but it is never silent:

  • the centre sum turns to the error colour and the vector stroke to the warning colour (:state(over-budget));
  • an "Over budget — explain why." panel appears below the radar with the exact overrun ("You're over budget by 1 point (5/4).") and a labelled Overrun rationale textarea (≥10 chars by default via data-min-overrun-rationale);
  • the element is invalid until that rationale is long enough, so a parent <form> won't submit (see Form association);
  • quality-target:over-budget and quality-target:under-budget fire once each time the selection crosses the capacity line.
const target = document.querySelector('quality-target'); target.addEventListener('quality-target:over-budget', (e) => { console.log(`Over by ${e.detail.delta} pts (${e.detail.criticalSum}/${e.detail.capacityPoints})`); }); target.addEventListener('quality-target:under-budget', (e) => { console.log(`Back within budget; ${e.detail.slack} pts of slack`); });

Form association

The element is form-associated: inside a <form> it submits the value JSON under its name (default quality). Its validity is reported through ElementInternals, so the form's own checkValidity(), reportValidity(), and native submit are blocked while a Critical pick lacks its rationale or an over-budget selection lacks its overrun rationale. When the overrun rationale is the problem, the browser points at that textarea. disabled takes the element out of validation entirely; locked keeps it submitting and validating, but read-only.

Accessibility

  • Keyboard. Each axis is a focusable role="button" (tabindex="0") inside an SVG role="group"; Enter and Space activate exactly like a click. Each axis's aria-label carries its name, level, and cost.
  • Editors. Each dialog is a native <dialog> (focus is trapped and returned by the browser, Escape closes it) with an aria-label naming the ility, a <fieldset>/<legend> radio group, and a labelled rationale textarea. Generated ids are unique per instance, so several targets on one page keep their labels straight.
  • Never colour-only. Priority levels are conveyed by the radio label text and each axis's accessible name, so the red/amber/green/muted coding is reinforcement rather than the only signal. Over budget surfaces as visible text with the exact overrun, plus a required, labelled rationale field, not just a colour change.
  • Disabled / locked. Mouse input is off, the axes leave the tab order and carry aria-disabled="true", openEditor() does nothing, and every dialog and footer control is disabled.
