Overview

A web component that renders a columnar drag-and-drop board with user-defined columns. Each column wraps a <drag-surface> for native drag-and-drop and keyboard-accessible reordering and transfer. Supports any draggable content — user-story cards, plain articles, or custom elements. Includes auto-updating count badges, optional WIP (work-in-progress) limits with visual warnings, and optional column color tinting.

WIP Limits

Add data-wip to any column section to set a work-in-progress limit. When the number of items in a column exceeds the limit, the component adds a data-wip-exceeded attribute to the column and fires a kanban-board:wip-exceeded event. Items are not blocked from entering — this is a visual warning only.

Property API (JS-first)

Reactive frameworks (Montane, Lit, Solid, Vue, React, Svelte) can drive the board directly with property assignments — no need to template the column structure. Existing card nodes whose id is in both the previous and next list are preserved across diffs: in-flight drag state, focus, and CSS animations survive untouched.

PropertyTypeDescription
.columns{ id, label?, wip?, color? }[]Replaces all columns and rebuilds the shell. Existing cards whose column is still present move (same DOM nodes) into the new columns; cards whose column is gone are removed from the board and from .items, and kanban-board:items-changed reports it. Setting an empty array clears the board.
.items{ id, column, ... }[]Setter runs a keyed diff. id is the key; column selects the target drag-surface. Other fields go to the renderer.
.renderItem(item) => ElementOptional custom item renderer. Default builds a <work-item> and applies fields via .data.
const board = document.querySelector('kanban-board'); // Wait for the upgrade signal before assigning. if (!board.hasAttribute('data-upgraded')) await new Promise(r => board.addEventListener('kanban-board:upgraded', r, { once: true })); board.columns = [ { id: 'todo', label: 'To Do', wip: 5 }, { id: 'doing', label: 'In Progress', wip: 3, color: 'warning' }, { id: 'done', label: 'Done', color: 'success' }, ]; // Assigning .items diffs against current cards. board.items = [ { id: 'PROJ-1', column: 'todo', title: 'Wire auth', type: 'task', priority: 'high' }, { id: 'PROJ-2', column: 'doing', title: 'Refactor cache', type: 'feature', priority: 'medium' }, ]; // Avoid feedback loops by ignoring drag-sourced changes: board.addEventListener('kanban-board:items-changed', (e) => { if (e.detail.source === 'drag') updateMyState(e.detail.items); });
HTML-first still works. If <kanban-board> has <section data-column> children at upgrade, they're parsed into the initial state. Setting .items later takes over data ownership without rebuilding what's already there.

JSON Data Mode

Set the src attribute to load board data from a JSON URL. The URL is fetched once; kanban-board:ready fires after the data has rendered. Changing src loads the new URL and replaces the board (the request for an older URL is aborted). ready fires once per board; every src load that renders also fires kanban-board:items-changed with source: 'src', so listen for that to react to later loads. Moving the board in the DOM keeps the loaded cards and does not refetch.

Items with a storyId, persona, action, or benefit field are rendered as <user-story> cards: persona, action, and benefit become <span slot="…"> children, title an <h3 slot="title">, and storyId, priority, status, points, and detail (default minimal) the matching attributes. All other items are rendered as <article class="kb-card"> showing text (or label / title).

Keyboard Navigation

Card keyboard support comes from the underlying <drag-surface>. Each card is one tab stop:

  • Tab moves between cards; Up / Down move focus within a column
  • Space grabs the focused card (Enter does too, except on a minimal <user-story>, see below)
  • While grabbed: Up / Down reorder within the column, Left / Right move the card to the previous / next column
  • Space or Enter drops the card; Escape cancels and puts it back

A minimal <user-story> card (as in the demo above) keeps its own action: Enter opens its detail dialog and Space grabs it. A click opens the dialog too.

Accessibility

  • The columns container has role="region", labelled by the title attribute. An untitled board is "Kanban board", numbered from the second board on a page ("Kanban board 2") so region names stay unique; give each board a title for a meaningful name.
  • Headings follow the page outline: the title (when set) is one level below the nearest heading before the board, and the column headings one level below that — or one below the page heading when there is no title — so levels are never skipped. Set heading-level (1–6) to choose the board's top level yourself.
  • Each drag-surface has an aria-label of the column label plus "items" (e.g. "Backlog items")
  • Each <drag-surface> is exposed as a list of its cards (role="list" / "listitem", kept in step as cards are added and moved). If any card is an element that may not be a list item, such as <article>, that surface is exposed as a labelled role="group" instead and the cards keep their own role. The drag-surface's own move announcements are moved to a hidden status region just after the list, since a list may only contain list items.
  • A visually hidden live region announces transfers between columns using the card's text and the column labels (e.g. "Wire auth moved from To Do to In Progress")
  • Count badges use <output> elements for live value updates
  • Respects prefers-reduced-motion: reduce
