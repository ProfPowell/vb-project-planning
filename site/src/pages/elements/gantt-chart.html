Overview

A web component that progressively enhances a semantic <table> into an interactive Gantt timeline. Without JavaScript, users see a fully readable data table with native <progress> bars and <time> elements. With JavaScript, the component renders a visual timeline with positioned bars, swim lane groups, milestones, progress fill, and a today marker.

How It Works

The component reads task data from the semantic table structure:

  • Task name — from the first <td> text
  • Start/end dates — from <time datetime="YYYY-MM-DD"> elements
  • Progress — from <progress value="..." max="...">
  • Metadata — from data-* attributes on the <tr>

Dates are calendar days in the viewer's local time zone: 2026-04-01 is shown as April 1 everywhere (it is not read as UTC midnight). Positions are measured in whole days, so daylight-saving changes don't shift bars. Each bar is positioned at left: (taskStart - rangeStart) / rangeDays * 100% with width: (taskEnd - taskStart) / rangeDays * 100%; the range runs from the earliest start to the latest end. The timeline granularity auto-adjusts based on the date range, or can be set explicitly via the view attribute; month and quarter ticks fall on the 1st of the month or quarter.

Data Mode

Load task data from JSON via the src attribute. It is fetched once when the element connects (whether src was set before or after) and again only when src changes; moving the element in the DOM does not refetch. The loaded tasks replace any child table, and the component generates a visually hidden table from them for screen readers. A "title" in the JSON sets the title attribute.

{ "title": "Q2 Roadmap", "tasks": [ { "id": "design", "name": "Design system", "start": "2026-04-01", "end": "2026-04-15", "progress": 75, "group": "Design", "status": "in-progress" }, { "id": "launch", "name": "Launch", "start": "2026-05-01", "end": "2026-05-01", "milestone": true, "depends": ["design"] } ] }
Progress. JSON and .tasks share one rule: a value greater than 1 is a percentage (75 = 75%), a value from 0 to 1 is a fraction (0.75 = 75%, 1 = 100%). In a table, <progress> is read as value / max. Values are clamped to 0–100%, and .tasks always reads back as a fraction.

Property API (JS-first)

For reactive frameworks, assign .tasks directly instead of templating the source <table>. Each task is a plain object; start/end accept YYYY-MM-DD strings, Dates or timestamps. Tasks without a valid start are dropped.

PropertyTypeDescription
.tasksTask[]Setter replaces the chart contents and re-renders, and regenerates the visually hidden table from the new tasks (the authored table is replaced). Assigned tasks survive moving the element in the DOM. Reading returns the normalized array: start/end are local-midnight timestamps, progress is 0–1, depends/storyIds/itemIds are arrays.
const g = document.querySelector('gantt-chart'); await new Promise(r => g.addEventListener('gantt-chart:upgraded', r, { once: true })); g.tasks = [ { id: 'T1', name: 'Design', start: '2026-04-01', end: '2026-04-15', progress: 0.6 }, { id: 'T2', name: 'Build', start: '2026-04-10', end: '2026-04-25', depends: ['T1'] }, { id: 'T3', name: 'Release', start: '2026-04-30', end: '2026-04-30', milestone: true }, ]; effect(() => { g.tasks = sprintTasks.get(); }); g.addEventListener('gantt-chart:tasks-changed', (e) => { if (e.detail.source !== 'property') syncStore(e.detail.tasks); });

An empty <gantt-chart> (no table, no src) still upgrades and fires gantt-chart:upgraded, so the JS-first pattern above works. A .tasks value assigned before the element is defined is picked up on upgrade.

v1 is record-shaped. Assigning .tasks rebuilds the entire chart. Per-bar preservation across diffs (to keep drag-resize state) is on the roadmap when consumers report it as a felt need.

Accessibility

  • The task table stays in the DOM (visually hidden) so screen readers get full table semantics with <th>, <time>, and <progress>. For .tasks and src data the component generates that table from the current tasks.
  • Each bar and milestone is a focusable role="button" whose accessible name gives the task name, dates, status, progress and assignee (e.g. “API development: Apr 10, 2026 to May 1, 2026, status: in progress, 40% complete”). Enter or Space activates it and fires gantt-chart:task-click.
  • Status is shown as text in the task list, not by bar colour alone.
  • An aria-live="polite" region announces task selection.
  • Dependency arrows are decorative (aria-hidden); dependencies are not announced.
  • Attribute-driven re-renders crossfade with a View Transition, skipped under prefers-reduced-motion: reduce; bar hover transitions are disabled there too.
  • Print styles show the table and hide the visual chart
